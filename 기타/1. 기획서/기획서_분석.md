## 1. 게임 개요 요약

1인용 **마을 노동 + 추리 게임**으로, 플레이어는 최근 이사 온 마을 주민이 되어 매일 밤 발생하는 **사보타주 사건의 범인**을 추리한다. 낮에는 밭일·채집으로 체력을 관리하며 7명의 NPC와 실시간 LLM 대화를 나눠 단서를 모으고, 밤에는 범인(매판 랜덤 배정)이 사보타주를 저지른다. **7일차부터 고발 가능**하며, 오답 시 8일차·9일차까지 재도전할 수 있고 9일차에도 실패하면 마을에서 쫓겨나는 **배드엔딩**, 성공하면 해당 범인의 개별 스토리가 공개되며 즉시 종료된다. 목표 플레이타임은 짧게 1~2시간, 길게 2~3시간이며, 재플레이 시마다 범인이 다시 랜덤 배정되는 반복 플레이 구조다.

### 2-2. 진행 스케줄 (9일 구조)

| 일차 | 내용 |
|---|---|
| 1일차 | 조사 시작 |
| 1~5일차 밤 | 매일 밤 사보타주 발생 (총 5회) |
| 2~6일차 | 전날 밤 사보타주 장소에서 단서 카드 습득 가능 (총 5장, 미습득 시 계속 남음) |
| 6일차 밤 | 사보타주 없음, 단서 없음 |
| 7일차 | **첫 고발 가능일.** 농사·채집만 가능, 주민과는 간단 대화만(추리 대화 불가) |
| 7→8일차 밤 | (오답 시) 마을/주민 대상 추가 이벤트 발생 |
| 8일차 | 재시도 가능, 마을 전체 분위기 무거워짐 |
| 8→9일차 밤 | (오답 시) 플레이어 대상 추가 이벤트 발생 |
| 9일차 | 마지막 재시도. 실패 시 배드엔딩 |

- 최소 7일(첫 고발 성공) ~ 최대 9일(끝까지 실패) 소요
- 오답 시: 지목당한 NPC 억울함 토로 연출 + 호감도 하락(본인 -30 / 가까운 관계 -10~15 / 무관계 -5)
- 7~8일 랜덤 이벤트: 마을 게시판 도발 쪽지, 특정 NPC 집 앞 정체불명 물건, 마을 공용시설 낙서·표식
- 8~9일 랜덤 이벤트(플레이어 대상): 협박 편지, 밭 훼손

### 2-3. 사보타주 시스템

- 유형 **3분류 고정**: 절도형(작물/과일 서리, 상점 물건) · 파손형(울타리, 벤치, 조각상, 화분) · 방해공작형(동물 풀어놓기, 작물에 나쁜 것 뿌리기) — 카테고리 자체는 추가 불가, 세부 항목만 추가 가능
- 범인은 매 판 랜덤 선정
- 기본적으로 범인은 자기 소유물을 안 건드리되, 낮은 확률로 본인 가게를 스스로 터는 척하는 특수 케이스 존재
- 낮 동선과 밤 사보타주가 목격담(NPC 대사)으로 연결됨

### 2-4. 낮 활동 & 경제 시스템

- 낮: 밭일/채집(체력 소모) + 주민 대화(체력 소모 동일) + 장소 단서 카드 수집을 동시 진행
- 체력 회복은 **직접 기른 농작물·채집한 과일로만** 가능 (구매 음식으로 회복 불가)
- 체력 0 → 기절 (다음날 70으로 시작) / 낮 시간 종료 → 자동 귀가 (패널티 없음)
- 남는 농작물은 상점에 판매해 씨앗·추리 아이템 구매 가능
- 과일 4종 중 매일 1~2개가 랜덤 등장, 과일별 자체 쿨다운(재생 주기) 존재
- **인벤토리 슬롯 7칸**

### 2-5. 체력 소모표

| 행동 | 체력 소모 | 비고 |
|---|---|---|
| 이동 1회 | 5 (운동화 착용 시 4) | |
| 대화 1세션 | 8 | |
| 파종/수확 1회 | 5 (각각) | |

### 2-6. 호감도 시스템

- 사용자-NPC 간 호감도 (NPC끼리의 관계와는 별개 개념), 100점 만점 중 50점(중립)에서 시작
- 대화 진행(주제 선택·반복 방문) 시 +2~5 소폭 상승
- 오답 지목 시: 본인 -30 / 가까운 관계 -10~15 연쇄 하락 / 무관계 -5
- 구간별 반응: 70점 이상(우호적, 단서·정보 먼저 제공) / 30~70점(기본 대화만) / 30점 미만(대화 회피·단답형, 단서 제공 안 함, 완전 차단은 아님)

### 2-8. 단서 카드 시스템

- 가짜 카드 없이 실제 단서만 사용, 대신 내용 자체를 애매하게 설계
- 총 5장, 사보타주 발생 장소에서 습득 (자동 지급 아님, 놓쳐도 계속 남아있음)
- 단서 카드만 모아보는 전용 UI 제작 예정
- 5가지 주제: 머리카락(색깔·길이) · 소지품(개인 물건, 범행 도구) · 발자국(크기·보폭, 모양) · 혈흔(1회성) · 자국(긁힌 자국, 도구 자국, 넘어진 흔적 등)

## 3. 미정/모호한 항목 체크리스트

전체적으로 문서는 위 섹션들에 ✅(확정) 표시를 붙였지만, **핵심 밸런스 수치가 담긴 세부 표들은 대부분 💡(제안, 검토·확정 필요)로 별도 표시**되어 있어 실제로는 "확정"이 아니라 "구조는 정해졌지만 수치는 초안" 상태에 가깝다.

- [ ] **사보타주 배정표 (주/보조 유형)** — 💡 **부분적으로만 존재.** "범인별 사보타주 대상 풀" 표에 NPC별 **주 유형**과 대상 풀(동기 초안 포함)은 제시되어 있으나 **최종 확정 아님**으로 명시됨. **보조 유형은 구체적으로 배정되어 있지 않음** — "주 유형 80% + 보조 유형 20%를 부여해 세 유형 모두에 7명이 걸치게 하자"는 **방향성 제안만 있고, NPC별로 보조 유형이 무엇인지는 미정**.
- [ ] **NPC 동기 스토리** — 부분 존재. 표에 "동기(초안)" 필드로 1줄짜리 짧은 문구만 있음 (예: 현수동 "마을 개발에 대한 반감"). **대화 페르소나 생성 LLM에 넣을 만한 상세 백스토리·서사 수준은 아직 없음.**
- [ ] **체력 게이지 수치** — 소모량(이동5/대화8/파종수확5/채집3)과 섭취 회복량(작물·과일별 표)은 명시됨. 그러나 **최대 체력치(게이지 총량)와 "일반적인 하루 시작 체력"이 명시되지 않음** — 기절 후 리스폰 값(70)만 나와 있어, 70이 최대치인지 일부 회복치인지 불명확.
- [ ] **낮 동선표(맵 이동 규칙 — 방향키 자유이동 기준 체력 소모 방식 포함)** — NPC별 위치 확률표(💡 미확정)는 있으나, **플레이어의 이동 체력 소모 단위("1회")가 자유이동(방향키 연속 이동) 상에서 정확히 무엇을 기준으로 하는지(타일 1칸? 일정 거리? 목적지 지정?) 정의가 없음.** 아래 4번 항목과 직결.
- [ ] **8→9일차 특별 아이템** — **문서에 해당 개념 자체가 없음.** 8→9일차 밤에는 "플레이어 대상 랜덤 이벤트(협박 편지, 밭 훼손)"만 기술되어 있고 "특별 아이템" 지급/사용에 대한 언급은 전혀 없음.
- [ ] **기절 페널티** — "체력 0 → 기절 → 다음날 70으로 시작"만 명시. 그 외 페널티(시간 손실, 해당 일차 조기 강제 종료, 아이템/골드 손실, 호감도 영향 등)가 있는지는 언급 없음.
- [ ] **농사/채집 가격표** — 표 자체는 존재(작물 4종·과일 4종, 성장/재생 주기·체력·수확량·판매가·섭취회복·씨앗가격까지 상세)하지만 **💡 제안 단계로, 최종 확정 아님.**
- [x] **인벤토리 슬롯 수** — ✅ **확정: 7칸.**

### 그 외 문서 자체에서 명시적으로 미정으로 남긴 부분
- 사보타주 유형이 서로 안 겹치면 캐릭터가 유형만으로 특정될 수 있다는 우려 → 보조 유형 도입 필요성이 제기됐으나 **구체안 미확정**
- 범인별 사보타주 대상 풀 표 전체가 "최종 확정 아님"으로 각주 처리됨
- 낮 동선 배치표, 농사/채집 데이터 표 모두 💡(제안) 상태

## 4. 기존 결정 사항과의 충돌 여부

| 기존 결정 사항 | 기획서 내용 | 판정 |
|---|---|---|
| 기술 스택 (Phaser.js+React+Spring Boot+LLM 프록시+MySQL) | 기획서에 기술 스택 언급 전혀 없음 ("AI 활용: 실시간 LLM 대화"라고만 기재) | 충돌 아님 — 기획서가 기술 구현을 다루지 않는 문서라 자연스러움. 다만 기획서 쪽에 기술 스택 관련 언급 자체가 없으므로 별도 조율 불필요 |
| 마을 이동 방식 (스타듀밸리처럼 방향키 자유이동) | 기획서엔 이동 방식(자유이동 vs 타일클릭)에 대한 명시적 언급이 없고, 대신 "**이동 1회당 체력 5 소모**"라는 **이산적(discrete) 단위** 수치만 존재 | ⚠️ **잠재적 충돌 — 확인 필요.** 방향키로 연속 자유이동을 하는데 "이동 1회"라는 단위 소모 방식이 어떻게 매핑되는지가 기획서에 정의돼 있지 않음. 타일 1칸당 소모? 일정 거리마다 소모? 이 부분은 기획 쪽과 다시 합의해서 기획서에 반영해야 함 |
| NPC 대화 구조 (페르소나 생성 LLM ↔ 대화용 LLM 분리, DB에 상세 성격 저장 후 대화 시 로드) | 기획서엔 이 아키텍처 언급이 전혀 없고 "실시간 LLM 대화"로만 기재. 다만 NPC 표의 성격·말투·예시대사, 범인 배정 시의 "동기(초안)" 필드가 **페르소나 생성 LLM의 입력 재료**로 그대로 쓰일 수 있음 | 충돌 아님 — 기술 아키텍처는 기획서 범위 밖. 다만 "동기(초안)"이 1줄 수준이라 페르소나 생성 프롬프트로 쓰기엔 **살을 더 붙일 필요**가 있음 (3번 체크리스트와 연결) |
| 게임 흐름 (낮 밭일/채집+대화+단서수집 → 밤 랜덤 사보타주 → **3일차 첫 고발 가능**, 오답 시 **2일차부터 재도전**) | 기획서: 매일 밤 사보타주는 **1~5일차**(5회)만 발생, **7일차가 첫 고발 가능일**, 오답 시 **8일차, 9일차**까지 순차 재시도, 9일차 실패 시 배드엔딩 | 🔴 **명백한 충돌.** 고발 가능 시점(3일차 vs 7일차)과 재도전 방식(2일차로 되돌아감 vs 8→9일차로 순차 진행)이 완전히 다름. 이 기획서가 최신 버전이라면 "기존 결정 사항" 쪽의 3일차/2일차 스케줄이 **구버전이므로 폐기하고 7~9일차 스케줄로 갱신**해야 함. 반대로 기존 결정이 최신이라면 기획서를 수정해야 함 — **어느 쪽이 최신인지 팀 확인 필요** |

### 5-3. 백엔드 API 엔드포인트 초안

**세션/진행**
- `POST /api/sessions` — 새 게임 시작 (범인·동기·낮동선 랜덤 배정)
- `GET /api/sessions/{id}` — 세션 상태 조회 (일차, 체력, 골드, 상태)
- `POST /api/sessions/{id}/day/advance` — 하루 종료 처리 (밤 사보타주 실행, 단서 생성, 다음날 전환)

**맵/NPC**
- `GET /api/sessions/{id}/npcs` — 오늘의 NPC 위치 목록 (동선 배치 반영)
- `GET /api/sessions/{id}/npcs/{npcId}` — NPC 상세 + 현재 호감도

**대화 (LLM 프록시 연동)**
- `POST /api/sessions/{id}/npcs/{npcId}/dialogue` — 대화 메시지 전송 → llm-proxy 호출 → 응답 반환, 체력 8 차감
- `GET /api/sessions/{id}/npcs/{npcId}/dialogue` — 대화 이력 조회

**농사/채집**
- `POST /api/sessions/{id}/farm/plant` — 파종
- `POST /api/sessions/{id}/farm/harvest` — 수확
- `POST /api/sessions/{id}/forage` — 채집

**단서/상점/인벤토리**
- `GET /api/sessions/{id}/clues` — 보유 단서 카드 목록
- `POST /api/sessions/{id}/clues/{clueId}/clarify` — 돋보기 사용, 문구 명확화
- `GET /api/sessions/{id}/shop/items` — 상점 아이템 목록
- `POST /api/sessions/{id}/shop/purchase` — 구매 (작물 판매도 동일 엔드포인트에서 처리하거나 별도 `sell` 분리 검토)
- `POST /api/sessions/{id}/inventory/use` — 소모품 사용 (거짓말탐지기/선물세트 등)

**고발/엔딩**
- `POST /api/sessions/{id}/accuse` — NPC 지목 (7일차부터 활성화, 정답/오답 판정 + 호감도 반영)
- `GET /api/sessions/{id}/ending` — 최종 결과 조회

**llm-proxy 내부 API** (backend가 호출, 기존 아키텍처 결정 — 페르소나 생성 LLM / 대화용 LLM 분리)
- `POST /internal/llm/persona/generate` — 세션 시작 시 NPC별 상세 페르소나 생성 → `npc_persona_state`에 저장
- `POST /internal/llm/dialogue` — 저장된 페르소나를 불러와 실시간 대화 응답 생성

## 참고 — 다음 논의가 필요한 우선순위

1. **일정 체계 확정 (4번 표 충돌)**: "7~9일차 순차 재도전" vs "3일차 첫 고발 + 오답 시 2일차 재도전" 중 최신 버전 확인 — 이후 모든 스케줄 관련 로직(사보타주 5회, 단서 5장 등)이 여기 종속되므로 최우선
2. **이동 체력 소모 단위**: 방향키 자유이동과 "이동 1회=체력5" 규칙을 어떻게 매핑할지 (타일 기준 등)
3. **보조 사보타주 유형 확정**: 유형만으로 범인이 특정되는 문제 해결 위해 NPC별 보조 유형 배정표 완성
4. **체력 최대치/일일 시작치** 명시
5. **기절 페널티**가 "다음날 70 시작"뿐인지 추가 페널티가 있는지 확정
