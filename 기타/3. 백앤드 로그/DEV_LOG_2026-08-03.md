## 4. llm-proxy 실제 LLM 연동
- Mock 응답이었던 `LlmService`를 Anthropic Java SDK(`com.anthropic:anthropic-java:2.34.0`) 기반 실제 Claude API 호출로 교체
- `AnthropicClientConfig`: `AnthropicClient` 빈 생성
- `GeneratedPersona`: 페르소나 생성 결과를 위한 구조화 출력(Structured Output) 스키마 — 대화용 LLM이 그대로 재료로 쓸 수 있게 배경 서사/동기/예시 대사까지 포함
- `generatePersona()`: Structured Output으로 NPC 기본 정보 → 상세 페르소나 확장 생성, 실패 시 대체 페르소나로 폴백
- `chat()`: 저장된 페르소나 + 대화 이력 기반 실시간 응답, 응답 속도를 위해 `thinking` 비활성화
- **`checkRefusal()` 추가**: Claude가 안전 정책상 응답을 거부(`stop_reason: "refusal"`)하면 명확한 예외로 걸러서 기존 폴백 로직으로 연결 (persona 생성/대화 응답 둘 다 적용)
- 모델은 `claude-sonnet-5`로 설정 (`LLM_MODEL` 환경변수, 비용/속도 이유로 opus-5에서 변경). 실제 Anthropic API 키도 `llm-proxy/application-local.yml`에 등록 완료

## 7. 로컬 빌드/실행 이슈 해결 (실제 검증 과정에서 발견한 버그들)
사용자 PC에서 `./gradlew build`를 실제로 돌려보면서 아래 4개의 진짜 버그를 순서대로 발견·수정함. **최종적으로 backend, llm-proxy 둘 다 `BUILD SUCCESSFUL`(테스트 포함, 실제 Aiven DB 연결 확인)까지 검증 완료.**

1. **Gradle Plugin Portal 색인 문제**: `org.springframework.boot:4.1.0` 플러그인이 Plugin Portal의 실제 "use API"에서 404 (사람이 보는 페이지엔 있는데 API 색인이 안 된 상태). → `settings.gradle`(backend/llm-proxy 둘 다)에 `maven { url 'https://plugins.gradle.org/m2/' }`를 `pluginManagement.repositories`에 직접 등록해서 우회
2. **`ObjectMapper` 빈 누락**: `spring-boot-starter-webmvc`가 이 Spring Boot 버전에서는 Jackson 자동 설정을 안 끌고 와서, `LlmService`(llm-proxy)와 `GameSaveService`(backend) 생성자 주입이 `NoSuchBeanDefinitionException`으로 실패. → 양쪽에 `JacksonConfig`(`@Bean ObjectMapper`) 추가
3. **backend에 `jackson-databind`가 컴파일 클래스패스에 아예 없었음**: llm-proxy는 Anthropic SDK가 우연히 Jackson을 끌고 와서 안 드러났던 문제. `spring-boot-starter-json` 추가로도 안 돼서, `jackson-databind`/`jackson-datatype-jsr310`을 `build.gradle`에 직접 명시해서 해결
4. **`GameSave.java`의 `@Comment` 위치 오류**: `@OneToOne @MapsId` 연관관계 필드에 `@Comment`를 붙이면 Hibernate가 "매칭되는 컬럼 없음"으로 거부. `@Id` 필드(`accountId`) 쪽으로 옮겨서 해결

## 9. llm-proxy 내부 API 인증
- `/internal/llm/**`이 그동안 아무 인증 없이 열려있었음 — 포트에 접근 가능한 누구나 Anthropic API를 대신 호출해 비용을 낼 수 있는 상태였음
- `InternalApiKeyFilter`(`OncePerRequestFilter`) 신설: `X-Internal-Api-Key` 헤더를 공유 비밀키와 `MessageDigest.isEqual`로 비교(타이밍 공격 방지), 불일치/누락 시 401

- 양쪽 `application.yml`/`application-local.yml.example`에 `INTERNAL_API_KEY` 배선, 실제 로컬 파일에도 반영해 온보딩 안 깨지게 함
